Key Default Type Description
source.dynamic-rate-limit.allocator
 "demand-aware" String How the global target rate is split across the source subtasks. 'demand-aware' is a max-min fair allocation based on the throughput each subtask reports, which copes with partition skew. Any other value is read as the fully qualified name of a RateAllocator with a public no-arg constructor.
source.dynamic-rate-limit.calculator
 "checkpoint-duration" String How the global target rate is derived after each checkpoint. 'checkpoint-duration' throttles down when checkpoint durations trend up and ramps up otherwise. Any other value is read as the fully qualified name of a RateLimitCalculator with a public no-arg constructor.
source.dynamic-rate-limit.enabled
 false Boolean Whether the source coordinator should track the rolling trend of checkpoint completion times and dynamically broadcast an adjusted target rate limit to source readers that opt in via RateLimiterStrategy#dynamic(double).
source.dynamic-rate-limit.max
 0.5 Double Upper bound of the checkpoint duration band, as a fraction of the checkpoint interval. While the latest checkpoint duration is above this value the rate is throttled down immediately.
source.dynamic-rate-limit.max-records-per-second
 1.7976931348623157E308 Double The ceiling (records per second, across all subtasks) that the dynamic rate limit is allowed to ramp back up to.
source.dynamic-rate-limit.min
 0.1 Double Lower bound of the checkpoint duration band, as a fraction of the checkpoint interval. While the latest checkpoint duration is below this value the rate is left unchanged.
source.dynamic-rate-limit.ramp-up-factor
 0.3 Double The factor the current target rate is multiplied by when checkpoint durations are flat or improving, capped at source.dynamic-rate-limit.max-records-per-second, e.g. 1.1 raises the rate by 30%.
source.dynamic-rate-limit.rolling-window-size
 3 Integer The number of most recent checkpoint durations to keep when computing the checkpoint-duration trend.
source.dynamic-rate-limit.target
 0.3 Double The desired checkpoint duration, as a fraction of the checkpoint interval, between source.dynamic-rate-limit.min and source.dynamic-rate-limit.max. The rate is throttled down while the average duration over the rolling window is above it and ramped up otherwise. Only applies when the checkpoint interval is known; otherwise the rate follows the checkpoint duration trend.
source.dynamic-rate-limit.throttle-down-factor
 0.8 Double The factor the current target rate is multiplied by when checkpoint durations are trending up beyond the configured threshold, e.g. 0.8 cuts the rate by 20%.
