Key Default Type Description
execution.checkpointing.coordinator-state-in-file.enabled
 false Boolean Whether operator coordinator state can be stored in its own file instead of inline in the root checkpoint metadata file. This applies only to file system checkpoint storage and to coordinators that can restore their state from a file, which include the coordinators of all sources built on the Source API. State smaller than 'execution.checkpointing.coordinator-state-inline-threshold' stays inline. If that option is not set, 'execution.checkpointing.data-inline-threshold' applies. The JobManager does not keep a copy of such state for its retained checkpoints, so every global failover, and every restart or rescale of the adaptive scheduler, reads it back from its file. Checkpoints and savepoints with coordinator state in its own file use a newer metadata format. Earlier Flink versions can neither restore them nor read the high availability entries of such checkpoints, so enable this only once you no longer need to roll back to an earlier version.
execution.checkpointing.coordinator-state-inline-threshold
 (none) MemorySize When 'execution.checkpointing.coordinator-state-in-file.enabled' is true, the state of operator coordinators that support it is stored in its own file on file system checkpoint storage unless it is smaller than this size, in which case it stays inline in the root checkpoint metadata file. If not set, 'execution.checkpointing.data-inline-threshold' applies. Unlike that option, it applies only to coordinator state and has no maximum. Empty state always stays inline.
execution.checkpointing.create-directories-on-job-start
 true Boolean Whether to create the directories of the checkpoint storage (for example the 'shared' and 'taskowned' directories) when the job starts. If set to false, they are created when the first checkpoint is triggered instead, which avoids blocking job startup on file systems where creating directories is a slow remote call, such as object stores.
WARNING: If set to false, an unusable checkpoint location is no longer detected when the job starts. It surfaces as checkpoint failures, and fails the job once the tolerable number of checkpoint failures is exceeded.
execution.checkpointing.create-subdir
 true Boolean Whether to create sub-directories named by job id under the 'execution.checkpointing.dir' to store the data files and meta data of checkpoints. The default value is true to enable user could run several jobs with the same checkpoint directory at the same time. If this value is set to false, pay attention not to run several jobs with the same directory simultaneously.
WARNING: This is an advanced configuration. If set to false, users must ensure that no multiple jobs are run with the same checkpoint directory, and that no files exist other than those necessary for the restoration of the current job when starting a new job.
execution.checkpointing.data-inline-threshold
 20 kb MemorySize The minimum size of state data files. All state chunks smaller than that are stored inline in the root checkpoint metadata file. The max memory threshold for this configuration is 1MB. This option also applies to the state of operator coordinators that can restore it from a file, when 'execution.checkpointing.coordinator-state-in-file.enabled' is true and 'execution.checkpointing.coordinator-state-inline-threshold' is not set.
execution.checkpointing.write-buffer-size
 4096 Integer The default size of the write buffer for the checkpoint streams that write to file systems. The actual write buffer size is determined to be the maximum of the value of this option and option 'execution.checkpointing.data-inline-threshold'.
